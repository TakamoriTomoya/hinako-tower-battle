# 人物タワーバトル - MVP仕様

## コンセプト
「どうぶつタワーバトル」のルールを踏襲し、キャラクターを人物（オリジナル画像に差し替え予定）にした、
2人対戦の物理演算タワー積みゲーム。

## 対象プラットフォーム
- Web（PC / スマホブラウザ）
- 今回はパスプレイ対戦（同一画面・オンライン通信なし）
- 将来的にスマホアプリ化も検討するが、今回はWebでMVPを作る

## ゲームルール
1. 共有の1本のタワーに、プレイヤー1・プレイヤー2が交互にキャラを落として積む
2. 手番のプレイヤーは、落とす前に左右移動できる
3. タワーが崩れた（駒が土台の外に落下した）場合、その駒を落としたプレイヤーの負け
4. 決着後はリスタート可能

## 操作
- 左右移動：矢印キー or 画面上の左右ボタン
- 落とす：スペースキー / 下矢印 or 画面上の「落とす」ボタン
- スマホでも操作できるようタップ操作を用意

## 技術構成
- `app/` 配下: React + TypeScript + Vite
- HTML5 Canvas + Matter.js（物理演算、npmパッケージ）
- ゲーム本体(Matter.js物理・Canvas描画・入力)はReactに依存しない`TowerBattleEngine`クラスに集約し、
  Reactは画面遷移・手番表示などUIの薄いシェルとして被せる構成
- 画像：実写切り抜き画像（`app/public/images/`）をそのまま駒として使用

## MVPスコープ（今回作るもの）
- 2人パスプレイのみ（CPU対戦・オンライン対戦は対象外）
- キャラは形状違いを数種類用意（積みにくさにバリエーションを持たせる）
- プレイヤーごとに色分け表示
- 崩壊判定・勝敗表示・リスタート機能
- 現在の手番・タワーの高さを画面に表示

## 今回は対象外（将来やること）
- オリジナル画像への差し替え
- スマホアプリ化（PWA化 or ネイティブアプリ）
- CPU対戦
- 高さスコアのランキング機能

## オンライン対戦（合言葉で部屋を作って対戦）

パスプレイに加えて、別々の端末から合言葉（自由な文字列）で同じ部屋に入り遠隔対戦できる。

- 通信方式: Firebase Realtime Database（Push型）。ホスト権威モデルを採用し、部屋を作った側
  （ホスト=プレイヤー1「ともや」）の端末だけが実際にMatter.jsを実行し、結果を配信する。
  入室した側（ゲスト=プレイヤー2「ひなこ」）は物理演算を行わず、受信内容をそのまま描画するミラー。
  （詳細は`src/lib/engine.ts`冒頭のコメント、`src/lib/network/`を参照）
- 合言葉はシステムが自動発行するのではなく、ホスト・ゲスト双方が同じ自由な文字列を入力する方式。
- プレイヤー名は既存の「ともや」「ひなこ」固定のまま（このアプリは実質2人専用のため）。

### セットアップ（このアプリを動かす人が最初に1回だけ行う）
1. [Firebaseコンソール](https://console.firebase.google.com/)でプロジェクトを作成し、
   Realtime Databaseを有効化する。
2. Web用アプリを追加し、表示されるconfig（apiKey, databaseURL等）を`.env.example`を参考に
   `.env.local`へコピーする。Vercelにデプロイする場合はVercel側の環境変数にも同じ値を設定する。
3. Realtime Databaseのルールを、認証なしで`rooms/{roomId}`配下のみ読み書きできる内容に設定する
   （合言葉を知っている=部屋のpathを知っている、という前提のカジュアルな保護。個人利用のため許容）:

```json
{
  "rules": {
    "rooms": {
      "$roomId": {
        ".read": true,
        ".write": true
      }
    },
    ".read": false,
    ".write": false
  }
}
```

パスプレイのみ使う場合、この設定は不要（オンライン対戦ボタンを押さない限り呼び出されない）。
